# Built-in comparison corpus.
#
# One entry per line: `Title @ revid | tag, tag`. Blank lines and `#` comments
# are ignored. Tags name the feature areas an entry is intended to exercise, so a
# failure can be attributed to a body of work rather than just counted.
#
# Entries are chosen to span the failure space, not to be representative of
# Wikipedia. Sizes and `#invoke` counts below were measured against enwiki; they
# will drift as pages are edited, which is why the harness pins revisions in its
# cache. Tags were verified by inspecting each page's wikitext, not assumed.
#
# A tag is only worth adding if it names something separately implementable; a
# taxonomy that mirrors the diff rather than the work would not prioritise
# anything.
#
# The `@ revid` pin belongs in this file, not only in the cache manifest: the
# manifest is the one file whose loss is unrecoverable, and a corpus that states
# its own revisions is what makes a scoreboard comparable across runs. An entry
# whose revision the cache no longer holds is reported as skipped rather than
# silently compared at a different revision.
